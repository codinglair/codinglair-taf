# Codinglair TAF 1.2.0 release notes

Release 1.2.0 adds capability-oriented starters, deterministic multi-capability Maven project
generation, and an official MCP Server container distribution. Runtime remains independently
usable without MCP or AI, and community artifacts contain no proprietary Quality Intelligence
code.

## Highlights

- Five top-level starters cover Web, API, Database, Messaging, and Mobile. Kafka, RabbitMQ, JMS,
  and AWS provider starters compose with the provider-neutral Messaging contract.
- The BOM aligns starter and direct-module coordinates without activating capabilities. Providers
  remain inert until their documented configuration is selected.
- Blueprint composition generates Maven projects from versioned capability contributions, rejects
  invalid combinations and collisions before publication, and never adds MCP merely because MCP
  initiated generation.
- `codinglair/codinglair-taf-mcp:1.2.0` supplies mutually exclusive STDIO and Streamable HTTP
  profiles in one non-root image. Reproducible automation uses the semantic tag or published
  digest, never `latest`.
- The Streamable HTTP image profile has a supported Kind reference deployment with OIDC,
  readiness/liveness probes, bounded resources, graceful shutdown, and explicit external secret
  references.
- Release conformance exercises each starter, all starters/providers together, supported
  direct-module consumers, generated projects, both image profiles, and Kubernetes restart from
  clean external boundaries.

## Compatibility and migration

This additive minor release removes or renames no supported 1.1.0 artifact coordinate. Existing
direct-module consumers may remain on that model; new consumers should import
`com.codinglair.taf:codinglair-taf-bom:1.2.0` and select capability starters. No Runtime lifecycle,
MCP v1 schema, persistent-data, or established configuration-key migration is required.

Secret providers now require explicit selection when starter composition makes more than one
provider available. This is a fail-closed security rule, not an automatic fallback. Provider
starters likewise require their documented enablement/configuration before creating clients,
listeners, connections, or resources.

## Qualification boundaries

- Maven is the supported generated-project build. Gradle examples validate dependency syntax only.
- Mobile generation targets Android/UiAutomator2; iOS/XCUITest is rejected as unsupported.
- The Kind topology is a single-replica reference deployment with process-local state. Restart
  qualification proves service recovery and does not claim durable jobs or approvals.
- The immutable Docker Hub digest, optional `latest` equality, signature, SBOM, provenance, and
  vulnerability disposition are produced only by the authorized image-publication workflow.
