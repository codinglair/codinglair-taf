# Codinglair TAF 1.1.0 release notes

Release 1.1.0 adds the optional AWS messaging capability to the Community Runtime and exposes its
configuration and evidence through the existing governed MCP workflows. Runtime remains usable
without MCP or AI, and no proprietary Quality Intelligence artifact is included.

## Highlights

- Separate typed `EventBridgeController` and `SqsController` APIs compose in one `TestSession`.
- SQS operations use bounded polling, explicit acknowledgement, controlled visibility, safe
  isolation strategies, and sanitized evidence.
- EventBridge route assertions verify delivery through an observable SQS target rather than
  treating EventBridge as an event store.
- `LocalStackEnvironmentProvider` provisions test-owned resources or validates declared external
  resources. Cleanup is ownership-bound, reverse ordered, and idempotent.
- The standalone AWS consumer resolves version 1.1.0 from an isolated staged repository and runs
  without reactor source access.
- Runtime and MCP artifacts ship together with source, Javadoc, CycloneDX SBOM, license metadata,
  and the existing compatibility and security gates.
- `McpContractResources` publishes stable classpath locations for the v1 MCP schema set and
  capability catalog, allowing the resource-first contract artifact to carry useful Javadocs.

## Compatibility and upgrade

This is an additive minor release. Existing 1.0.0 Runtime and MCP configuration remains valid. To
adopt AWS messaging, import `codinglair-taf-bom:1.1.0`, add `taf-messaging-aws`, and configure the
`taf.aws` namespace. No Runtime Core, MCP schema, persistent-data, or configuration-key migration is
required. AWS SDK types do not enter Runtime Core contracts.

Use dedicated queues or namespaces by default. Correlation-only observation of a shared queue is
rejected unless the test has controlled-consumer ownership. Existing applications that implemented
unsafe shared-queue scanning must move to a dedicated resource, dedicated namespace, or approved
controlled consumer before enabling the capability.

See the [AWS messaging guide](../reference/aws-messaging.md),
[compatibility matrix](../engineering/compatibility-matrix.md), and
[release packaging guide](../operations/release-packaging.md).

## Qualification boundary

LocalStack 4.14.0 is the qualified emulator. It does not prove AWS IAM, quota, throttling, latency,
or regional behavior. Authorized-AWS qualification is performed only through the protected release
environment after explicit approval. If that environment is unavailable, release approval must
explicitly accept the NFR-016 exception; the check must not be described as passed.
