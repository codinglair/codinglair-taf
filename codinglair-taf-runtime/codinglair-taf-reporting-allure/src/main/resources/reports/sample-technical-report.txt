EXECUTIVE SUMMARY
-----------------
This technical report provides an overview of the Codinglair Test Automation
Framework (TAF) Runtime implementation using the Allure reporting adapter.
The Allure adapter provides vendor-specific reporting capabilities while
maintaining a vendor-neutral TestReporter SPI.

ARCHITECTURE OVERVIEW
---------------------
The TAF Runtime follows a modular architecture with the following key components:

1. Core Runtime (codinglair-taf-runtime-core)
   - TestSession: Manages isolated test execution context
   - ControllerRegistry: Typed, named controller instances
   - ArtifactCollector: Manages test artifacts with sanitization
   - RedactionPipeline: Secret redaction and SHA-256 hashing

2. Allure Adapter (codinglair-taf-reporting-allure)
   - AllureReporter: Implements TestReporter SPI for Allure
   - AllureListener: Provides Allure lifecycle access
   - Thread-safe lifecycle management

3. Common Utilities (codinglair-taf-common)
   - Core data types (Error, Capability)
   - Annotations (@TafStep, @TafDescription, @CaptureOutput)
   - AspectJ weaving for reporting

REPORTING MODEL
---------------
The Allure adapter implements the following reporting model:

- Feature: "TAF Runtime Tests"
- Epic: "Allure Integration"
- Soft Story: "Test Execution"
- Test: Individual test execution with unique ID
- Step: Individual test steps with status tracking
- Artifact: Attachments with sanitized content

LIFECYCLE MANAGEMENT
--------------------
The AllureReporter manages the following lifecycle operations:

1. beginTest(test)
   - Creates unique test ID
   - Initializes test result with running status
   - Sets up test description from className

2. endTest(test)
   - Determines final status from step outcomes
   - Updates test result with final status
   - Publishes test result to Allure
   - Cleans up test-specific state

3. reportStep(step)
   - Creates unique step ID
   - Records step description and status
   - Associates step with parent test
   - Tracks step in memory for status computation

4. reportArtifact(artifact)
   - Sanitizes artifact content
   - Removes secrets and sensitive data
   - Computes SHA-256 hash for integrity
   - Attaches to current test context

SANITIZATION
------------
All content passed through the Allure adapter is sanitized to prevent
leakage of sensitive information:

- Passwords, tokens, and credentials are redacted
- API keys and secrets are replaced with [REDACTED]
- SHA-256 hashes computed for content integrity verification
- Class names sanitized to remove package information
- Test names sanitized to remove special characters

THREAD SAFETY
-------------
The AllureReporter is designed for concurrent test execution:

- ThreadLocal storage for current test context
- ConcurrentHashMap for test-step mapping
- Atomic counters for global metrics
- Idempotent cleanup operations

USAGE EXAMPLE
-------------
```java
import com.codinglair.taf.runtime.core.reporting.abstraction.*;
import com.codinglair.taf.runtime.core.reporting.impl.allure.AllureReporter;

public class MyTest {
    private final AllureReporter reporter = new AllureReporter();

    @BeforeTest
    public void setUp() {
        TafTest test = TafTest.of("User Login", "com.example.LoginTest");
        reporter.beginTest(test);
    }

    @Test
    public void loginWithValidCredentials() {
        // Step 1: Navigate to login page
        reporter.reportStep(TestStep.of("Navigate to login page", "passed"));
        
        // Step 2: Enter credentials
        reporter.reportStep(TestStep.of("Enter username and password", "passed"));
        
        // Step 3: Click login button
        reporter.reportStep(TestStep.of("Click login button", "passed"));
        
        // Step 4: Verify successful login
        reporter.reportStep(TestStep.of("Verify dashboard displayed", "passed"));
    }

    @AfterTest
    public void tearDown() {
        TafTest test = TafTest.of("User Login", "com.example.LoginTest");
        reporter.endTest(test);
    }
}
```
